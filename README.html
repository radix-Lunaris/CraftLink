1. 这是什么

CraftLink 让 Minecraft 的玩家之间直连：一台「中继服务器」只负责撮合与信令， 真正的游戏数据走 P2P 打洞通路。房间的房主（Owner）不可转移，房主离开即销毁房间。

组件是什么跑在哪
server/ 中继账号、房间、成员状态机、信令、版本门Docker 容器 mc-relay
panel/ 面板PHP 管理面板 + 自带 nginx（端口 / 安全入口 / 域名 / SSL / 账号）Docker 容器 mc-panel
client/ 客户端Windows 单文件 CraftLink.exe（Python + tkinter，免安装）玩家自己的电脑
数据库MySQL / MariaDB：账号、房间、面板设置已有容器则复用，没有才由 compose 起
两套版本号，别混
服务端 / 客户端
3.9.x 一条线；权威值是 server/VERSION，客户端必须完全一致才能连接
面板
2.x 独立一条线（当前 2.11.45），与上面那条无关

2. 部署前置条件

项目要求说明
服务器Linux（x86_64 / arm64 均可），1 核 1G 起步中继本身很轻；实际瓶颈是 Docker 与数据库
权限root（或 sudo）安装器要写安装根目录、装 mclink 管理台
DockerDocker Engine + Compose v2（docker compose）安装器只做探测，不替你装 Docker
Pythonpython3（3.10+；中继容器镜像用 3.12）安装/迁移脚本用；只用标准库
数据库可选：本机 Docker 里已有 MySQL / MariaDB能读到就直接复用（建库建账号），读不到由 compose 起一个
端口TCP 19100（中继）、UDP 3478/3479（STUN）云安全组必须放行；面板端口见下一节
客户端Windows 10/11 64 位单文件 exe，免安装；Linux 也可以源码运行（需要 tkinter）
不要写死路径 安装根目录默认 /opt/mc-link，但这是默认值：安装器问你、或用 --root / MCLINK_ROOT 指定。下面所有命令里的 <安装根目录> 都换成你自己的。

3. 一条命令安装（服务端）

  1. 把交付包（deploy/ 目录里的全部内容）上传到服务器上任意目录。
  2. 在该目录执行下面这一条命令，然后按提示回车：
bash install.sh

它一次做完这些事（幂等：重复跑不会换掉已有凭据、不会重建数据库、不会动已有数据）：

步骤做了什么
1. 探测数据库读本机 Docker 里已有的 MySQL / MariaDB，拿容器里的 root 凭据建库建账号；探测不到就提示手动配置，不猜
2. 交互确认安装根目录、面板监听端口、URL 安全入口
3. 写 .env权限 600；凭据是本机随机生成的（不是包里的示例值）
4. 起服务构建并启动中继 + 面板容器，最后打印访问方式
5. 装管理台把 mclink 命令软链到 /usr/local/bin

3.1 非交互（自动化 / 重装）

bash install.sh --yes \
  --root /opt/mc-link \
  --panel-port 19102 \
  --secret-path my-panel-entry \
  --db-container web-mysql80

bash install.sh --help     # 全部参数

常用参数：--root（安装根目录）、--panel-port（面板端口）、 --secret-path（安全入口，留空=随机）、--db-container（指定复用的数据库容器）、 --no-start（只做准备、不起容器，排障用）、--rotate-secrets（强制换凭据）。

3.2 安装完先记住这些默认值

东西默认备注
安装根目录/opt/mc-link可自定义；脚本一律从自身位置推导
中继协议端口TCP 19100安全组放行
STUNUDP 3478 / 3479打洞用；安全组放行
面板入口http://<服务器IP>:19102/<安全入口>/默认只绑 127.0.0.1；对外访问见第 4 节
本机急救入口http://127.0.0.1:19103/安全入口 / 域名 / 证书配错时从这里进去改回来
凭据文件<安装根目录>/.env（600）不随发布包替换，升级时原样保留

3.3 日常命令（SSH 管理台 mclink）

root-only、免密码；每个动作都写审计日志（<安装根目录>/logs/mclink-console.log）。

命令用途
mclink status服务状态 + 最近日志
mclink show-secrets显示 .env 里的凭据（root）
mclink reset-entry / mclink set-entry [PATH]清空 / 重设面板 URL 安全入口（被关在门外时救命）
mclink unbind-domain解绑域名绑定
mclink ssl-status / mclink ssl-off看证书状态 / 关掉面板 HTTPS（证书不删）
mclink apply-network把「面板设置」里的监听地址 / 端口 / SSL 落到宿主机（重建面板容器）
mclink rescue打印本机急救入口地址
mclink reset-root-password / mclink reset-sessions改账号密码 / 强制所有人重新登录面板
mclink audit [N]看审计日志

重建（改完配置、传完新文件之后跑）：bash <安装根目录>/rebuild.sh； 只重建面板用 bash <安装根目录>/rebuild.sh panel（不断开玩家）， 只重建中继用 ... relay（会断开在线玩家）。

4. 首次配置（端口 / 安全入口 / 管理员）

4.1 面板端口与安全入口

做法怎么做
装的时候定bash install.sh --panel-port 19102 --secret-path my-entry
装完改面板 →「面板设置」→ 监听 IP / 端口 / URL 安全入口；保存后执行 mclink apply-network
忘了安全入口SSH 里 mclink reset-entry（清空）或 mclink set-entry（重设）
安全入口 ≠ 认证 它只是把面板藏到一个随机路径上，绕过它仍然要登录。真正的访问控制是账号密码 + HTTPS。

4.2 让面板能从外面访问（二选一）

路子步骤适合
A. 面板自带 nginx 直听（M4 起，推荐） 面板 →「面板设置」→ 监听 IP 改 0.0.0.0（或直接配域名 + SSL）； 执行 mclink apply-network；云安全组放行该端口 不想装别的面板；要用面板自带的证书 / ACME
B. 用 1Panel / 宝塔反代（旧部署兼容） 建一个反向代理站点 → 目标 http://127.0.0.1:19102， 由它终结 HTTPS 已经有 1Panel，且想让它统一管证书
两条路不要同时管域名 走 B 的时候，不要在面板里再开「绑定域名」+「强制 HTTPS」——两边都判 Host 会互相打架。 要么域名绑定在面板（A），要么在 1Panel（B）。

4.3 管理员账号（第一次登录用）

  1. 编辑 <安装根目录>/server/docker-compose.yml，把这一行填上你的管理员账号： 
    MCLINK_BOOTSTRAP_ADMIN: "admin:换成你的强密码"
  2. 重建中继：bash <安装根目录>/rebuild.sh relay（中继启动时创建这个账号）。
  3. 创建成功后马上把那一行清回 ""，再跑一次 rebuild.sh relay —— 别让明文密码留在 compose 文件里。
  4. 用这个账号登录面板 →「账号」页给朋友们建账号（客户端不提供注册）。
  5. 忘记密码：SSH 里 mclink reset-root-password。

4.4 面板里建议顺手做的三件事

  1. 「面板设置」→ 绑定域名 + 上传证书（离线可用）或 Let's Encrypt（需域名解析 + 80 端口）。
  2. 「面板设置」→ 会话时长（默认 360 分钟）、未认证返回码。
  3. 「面板设置」→ 房间人数上限（默认 64，范围 2–64；改了立即生效，不用重启）。

4.5 装完自检

# 容器健康
docker ps --filter name=mc-relay --filter name=mc-panel

# 中继健康接口（本机）
curl -s http://127.0.0.1:19100/health

# 中继日志
docker logs --tail 50 mc-relay

# 重建 + 文件指纹自证（传过文件之后必跑）
bash <安装根目录>/rebuild.sh

5. 客户端：怎么装、怎么填服务器地址

5.1 拿到客户端

形态怎么用
CraftLink.exe（单文件，免安装）拷到 Windows 上双击即可；另有带黑窗的 CraftLink-console.exe 用于排错
Windows 安装包 CraftLink-Setup.exe若发布包带了安装器：双击安装，可自选安装目录与数据目录
源码运行（Linux / 开发）python3 client/main.py（需要 tkinter）

5.2 首次运行：填服务器地址

  1. 双击运行。首次启动会弹一个非模态引导窗（不挡着你操作主界面）。
  2. 在「中转服务器」卡片里填两项： 服务器地址 = 部署者给你的域名或 IP；端口 = 部署时定的数字（默认 19100）。
  3. 点「测试服务器连接」。成功即被记住，下次自动带出；随时可改，改完立即生效。
  4. 登录 / 进房：账号由服务器管理员在面板「账号」页创建，客户端不提供注册。
这几件事是设计如此，不是 bug
默认没有服务器地址
客户端不预置任何域名/IP，必须手填
登录记忆默认不记
用户名/密码默认不写盘；你主动勾选才记
数据目录可改
配置/日志默认在 %APPDATA%\CraftLink（Linux：~/.config/CraftLink），绝不写进程序安装目录

5.3 版本必须一致（连不上先看这条）

中继有一道版本门：客户端握手行里的 ver= 必须等于服务器的 server/VERSION，否则服务端直接回 ERROR VERSION_MISMATCH server=… client=…，客户端弹「需要更新」并停止重连。

升级服务端就必须同时升级客户端 只升一边 = 所有客户端都连不上（这是故意的：不同版本的协议约定可能不同，宁可明确拒绝，也不产生看不懂的怪现象）。

6. ★ 从 3.9.20 升级到本版本

下面用 3.9.21 代表「你要升到的那一版」；实际值看发布包里的 server/VERSION。3.9.20 是你现在跑的版本。 所有命令里的 /opt/mc-link 换成你自己的安装根目录。

6.1 升级前后各做什么（先看这张表）

阶段动作为什么
升级前备份数据库 + .env + data/ + config/回滚的唯一依据
升级前记下当前 current 指向的版本目录回滚就是把它指回去
升级中新版本解到 releases/<新版本>/，不要就地覆盖老目录保留"上一版可回滚"
升级中.env、数据库、data/、config/ 不搬家、不替换它们是版本目录之外的状态
升级后切 current 软链 → 重建容器原子切换；出问题一条命令切回
升级后把面板从 1Panel 反代切到自带 nginx（如果要切）：放行新端口、下线旧反代见 6.4
升级后客户端升到同一版本版本门；否则全员连不上
升级后验收：健康接口 / 面板登录 / 真客户端进房见 6.6

6.2 备份（先做，5 分钟）

ROOT=/opt/mc-link
TS=$(date +%Y%m%d-%H%M%S)
BK="$ROOT/backups/$TS"
install -d -m 700 "$BK"

# 1) 数据库（库名/账号默认 mclink；用 .env 里的密码）
set -a; . "$ROOT/.env"; set +a
docker exec "$(docker ps --format '{{.Names}}' | grep -iE 'mysql|mariadb' | head -1)" \
  mysqldump -u "${MCLINK_DB_USER:-mclink}" -p"$MCLINK_DB_PASSWORD" \
  "${MCLINK_DB_NAME:-mclink}" > "$BK/mclink.sql"

# 2) 凭据与运行期状态（升级不替换它们，但要有备份）
cp -a "$ROOT/.env" "$BK/.env"
tar -czf "$BK/data-config.tar.gz" -C "$ROOT" data config 2>/dev/null || true

# 3) 记下当前版本（回滚要用）
readlink -f "$ROOT/current" | tee "$BK/current-before.txt"
ls -l "$ROOT/releases" | tee -a "$BK/current-before.txt"
备份里有什么，别外传 mclink.sql 有全部账号数据，.env 有数据库密码与管理 API token。 权限保持 600/700，不要放进网盘或工单。

6.3 原地升级（release 目录 + current 软链）

ROOT=/opt/mc-link
NEW=3.9.21          # 换成发布包里的 server/VERSION
OLD=$(basename "$(readlink -f "$ROOT/current")")

# ① 解到新版本目录（保留老目录 = 保留回滚能力）
install -d -m 755 "$ROOT/releases/$NEW"
tar -xzf release-$NEW.tar.gz -C "$ROOT/releases/$NEW"      # 按发布包实际结构调整 --strip-components

# ② 把"版本目录之外的状态"接给新版本：
#    .env / data/ / config/ 本来就在 $ROOT 下，不在 releases/<版本>/ 里，
#    所以这里【什么都不用拷】—— 这正是它们能在升级中活下来的原因。
#    如果你的部署把 .env 放在 releases/<版本>/ 里，请先把它移到 $ROOT/.env。

# ③ 原子切换（先建临时软链再 mv，避免"切到一半"）
ln -sfn "$ROOT/releases/$NEW" "$ROOT/current.new" && mv -Tf "$ROOT/current.new" "$ROOT/current"

# ④ 用稳定入口重建并拉起（内部指向 current）
bash "$ROOT/rebuild.sh"
你的部署里还没有 releases/ + current？ 那说明它是"整包覆盖"式部署（deploy/ 直接铺在 $ROOT 下）。 同一个流程改成两步即可，回滚也简单：
  1. 升级：先 cp -a "$ROOT" "$ROOT.bak-$TS"（或只备份将被覆盖的 server/ panel/ scripts/ tests/ *.sh *.yml），再把新包内容覆盖进 $ROOT， 最后 bash "$ROOT/rebuild.sh"；
  2. 回滚：把备份覆盖回去 + bash "$ROOT/rebuild.sh"。
两种方式的共同点：.env、数据库、data/、config/ 都不动。

6.4 数据库与 .env 迁移

东西怎么处理注意
数据库数据 不迁移、不导入：继续用原来那个 MySQL/MariaDB 容器和 mclink 库 新版本的表结构变化都是 CREATE TABLE IF NOT EXISTS 式的懒建，启动时自动补齐
连库凭据 .env 保留原文件（600）；新版本的 compose 读同一份 不要用发布包里的 .env.example 覆盖它；也不要在升级时跑 --rotate-secrets（那会换密码，得同步改库）
面板设置 不用动：DB 表 panel_settings 是主存储，config/panel-settings.json 是备份 域名绑定 / 端口 / 安全入口 / SSL 设置都保留
证书与上传 不用动：data/panel-certs/、data/panel-uploads/ 目录属主需要时按发布说明 chown 65534:65534
compose 里的手改 会被新包覆盖（含第一次填的 MCLINK_BOOTSTRAP_ADMIN、硬编码的凭据行） 升级后按第 4.3 节重新确认；密码已经在库里的不用再设

6.5 面板：从「1Panel 反代」切到「自带 nginx」

3.9.20 之前的常见形态是：1Panel 反代 http://127.0.0.1:19102，由 1Panel 终结 HTTPS。 新版本的面板自带 nginx，可以自己终结 HTTPS，不再依赖 1Panel。

要做的事（按顺序）

  1. 先决定谁终结 TLS：继续让 1Panel 管（那就什么都不用切，保持旧形态即可）； 或者改成面板自带 nginx（下面继续）。
  2. 面板 →「面板设置」→ 绑定域名 + 证书：
    • 上传证书：fullchain.pem + privkey.pem（离线可用）；
    • 或 Let's Encrypt 自动申请 / 续期（需域名解析 + 80 端口能从公网进来）。
  3. 面板 →「面板设置」→ 监听 IP 改成 0.0.0.0（或按需），保存。
  4. SSH 执行 mclink apply-network（等价于 bash scripts/panel-apply.sh）—— 它会把 80 / 443 的映射加上并重建面板容器。
  5. 云安全组 / 防火墙：
    端口动作为什么
    TCP 80放行ACME 校验 + HTTP→HTTPS 跳转（开了 SSL 才需要）
    TCP 443放行面板 HTTPS 直听
    TCP 19102可关闭（不再对公网）改由 443 进来；本机调试仍可用
    TCP 19100 / UDP 3478-3479保持放行中继与 STUN，和面板无关
  6. 下线 1Panel 那条反代：1Panel →「网站」→ 停用/删除指向 19102 的代理站点， 并关掉它的"强制 HTTPS"。
  7. 验收：curl -sI https://你的域名/ 返回 200； curl -sI http://你的域名/ 301 到 HTTPS。
切换时最容易出的两个错
  • 1Panel 的反代和面板自带的 nginx 同时抢 80/443 —— 容器启动会明确报错（不会静默顶掉），看到端口占用就先去停一边；
  • 两边都做域名绑定 / 强制 HTTPS —— 请求的 Host 对不上，会看到 404 或无限跳转。只留一边。
进不去的时候：SSH 里 mclink rescue 拿到 http://127.0.0.1:19103/， 那个入口不判安全入口 / 不判域名 / 不跳 HTTPS。

6.7 回滚（出问题 3 分钟内切回）

ROOT=/opt/mc-link

# ① 切回旧版本目录（软链是原子操作，不会"切一半"）
OLD=$(cat "$ROOT/backups/<TS>/current-before.txt" | head -1)
ln -sfn "$OLD" "$ROOT/current.new" && mv -Tf "$ROOT/current.new" "$ROOT/current"

# ② 拉起旧版本
bash "$ROOT/rebuild.sh"

# ③ 只有"数据层也动过"才需要恢复数据库（正常升级不需要）
#    docker exec -i <db容器> mysql -u mclink -p"$MCLINK_DB_PASSWORD" mclink < "$ROOT/backups/<TS>/mclink.sql"

# ④ 把面板入口切回旧形态（如果这次动过 1Panel 反代 / 证书，按 6.5 反向做一遍）
回滚为什么这么快 数据库、.env、data/、config/ 都在版本目录之外， 升级过程没有替换它们 —— 所以"回滚"通常只是把 current 指回去再重建。

6.8 兼容性边界（哪些保留、哪些必须重设）

类别项目升级后
会被保留MySQL 数据（账号、房间、面板设置表）原样保留
.env（数据库密码、管理 API token）原样保留（600）
panel/config.php原样保留（发布包不会覆盖它）
data/panel-uploads/（logo 等）原样保留
data/panel-certs/（证书与私钥）原样保留
config/panel-settings.json（设置备份）原样保留
客户端数据目录（记住的服务器地址）原样保留，不用重填
会被覆盖 / 必须重做 server/ panel/ scripts/ tests/ *.sh *.yml被新包覆盖（这正是升级）
compose 里的手改（MCLINK_BOOTSTRAP_ADMIN、硬编码凭据行）丢；账号已在库里则不用重建，凭据按新的 .env/compose 对齐
系统层端口放行（安全组 / 防火墙）要自己加：80/443（自带 nginx）、19100、UDP 3478-3479
1Panel 反代站点切到自带 nginx 时要下线，否则抢 80/443
客户端必须升到同一版本（版本门）
本机生成的 panel/docker-compose.panel-ssl.yml不随包发布；执行 mclink apply-network 会按当前设置重新生成

7.2 门禁与回归

# 回归网（随包交付，纯标准库、不需要网络）
XDG_CONFIG_HOME=$PWD/.testcfg python3 tests/run_all.py

# 面板静态门禁（HTML/PHP/JS 契约，不需要数据库）
python3 tests/panel_static_test.py

# 挑和改动相关的专项套件（自己起中继、用完自己收）
XDG_CONFIG_HOME=$PWD/.testcfg python3 tests/v2_control_test.py
XDG_CONFIG_HOME=$PWD/.testcfg python3 tests/room_settings_test.py
XDG_CONFIG_HOME=$PWD/.testcfg python3 tests/host_offline_owner_test.py
XDG_CONFIG_HOME=$PWD/.testcfg python3 tests/version_gate_test.py

发版 / 打包门禁顺序固定，不要跳步：

python3 scripts/make_build.py --clean     # ① 清本地产物 + 重新生成 BUILD.txt / README.txt
python3 scripts/check_deploy.py           # ② 门禁 8 项（版本/凭据/指纹/编译/e2e/回归…）
python3 scripts/check_deploy.py --stamp   # ③ 全绿之后才打"这一版已发"的戳
python3 scripts/bump-version.py <x.y.z>   # ④ 最后才升版本号（唯一来源：客户端 APP_VERSION）
为什么是这个顺序 check_deploy.py 校验的是"BUILD.txt 和源码树是否一致"， 所以生成清单必须在门禁之前；--stamp 只能在全绿之后（它记录"上一版已发出"）； 升版本号会改两个版本文件，改完要重新 ①→②→③ 走一遍。

7.3 品牌定制（branding.json）

客户端启动时按顺序找第一个存在的 branding.json： $MCLINK_BRANDING_FILE → 程序目录旁（冻结 exe = exe 所在目录；源码运行 = client/） → 打包进 exe 的那份。模板见 client/branding.json.example。

字段类型默认作用
app_name字符串CraftLink窗口标题、页眉、关于页、日志首行
logo_file字符串空（内置图标）相对 = 相对 branding.json；绝对 = 原样
default_server_host字符串空新用户地址预填值、「恢复默认」的目标
default_server_port整数0（未设置）同上，只接受 1–65535
update_url字符串空版本不一致时「需要更新」弹窗里的下载页；空则只提示"向管理员索取"

未知字段被忽略；任何字段缺失都逐项回退，文件坏了只警告、不阻塞启动。 改品牌不用重新打包：把 branding.json 放到 exe 旁边即可。

7.4 可选组件（optional/）

目录是什么官方态度
optional/site/早期官网（纯静态 HTML/CSS/JS + nginx 站点配置）不再提供；想搭官网自行用宝塔 / 1Panel 的静态站点功能，页面可参考这里的实现
optional/checksum/下载哈希校验（发布前比对页面 SHA-256 / 字节数 vs 真实文件）不再提供；只对"自己发 exe 的官网"有意义
它不随包发布 scripts/make_build.py 把整个 optional/ 排除在 BUILD.txt / README.txt 之外：服务器上不会有它。 主交付的脚本/文档不许引用它下面的路径（包里没有 = 死链）。 交付包的完整性由另一套机制保证，仍然随包走：sha256sum -c BUILD.txt。

8. 常见问题速查

现象多半是怎么办
客户端提示"需要更新" / 服务端日志 VERSION_MISMATCH客户端与服务端版本不一致把客户端升到与 server/VERSION 相同的版本
面板打不开（404 / 空白）安全入口不对，或反代前缀被剥掉了mclink reset-entry；或 mclink rescue 用本机急救入口
面板跳转死循环 / 4041Panel 反代与面板自带 nginx 同时管域名只留一边（见 4.2 / 6.5）
容器起不来，报端口占用80/443 被别的站点占着停掉冲突站点，或改面板监听端口
玩家连不上中继安全组没放行 TCP 19100放行；curl -s http://<IP>:19100/health 自测
能进房但打不通 P2PUDP 3478/3479 没放行（NAT 类型差也会）放行 UDP；看客户端日志里的 NAT 结论
改完文件没生效镜像用了构建缓存bash <安装根目录>/rebuild.sh（它会先删镜像再构建）
数据库连不上.env 与 compose 里的值不一致以 .env 为准对齐；mclink show-secrets 查看
