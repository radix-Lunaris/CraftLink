# `optional/` —— 可选组件（不随主交付发布）

> **这一整目录都不是主交付的一部分。**
>
> 官方发布的服务端交付包（`deploy/` 那份目录结构、`BUILD.txt` 指纹清单、
> `scripts/make_build.py` 生成的清单）里**没有** `optional/`：
> `scripts/make_build.py` 的排除规则把整个目录排除在外，服务器上也永远不会
> 出现它。它留在仓库里，只是把「我们早期自己实现过、现在**不再提供**的两项
> 附加能力」原样留档，供未来的开发者参考或自行实现。

## 1. 这里有什么

| 目录 | 是什么 | 官方态度 |
|---|---|---|
| `site/` | 早期官网（纯静态 HTML/CSS/JS + nginx 站点配置） | **不再提供**。想要官网请自己用宝塔 / 1Panel 的「静态网站」功能搭，页面可直接参考这里的实现 |
| `checksum/` | 下载页哈希校验（发布前自检：页面上的 SHA-256 / 字节数和 exe 对不对得上） | **不再提供**。它只对「我们自己发 exe 的官网」有意义；现在客户端由你自行分发，是否做哈希公示由你决定 |

两件事都不影响服务端运行：主交付（中继 + 面板 + 客户端）**不依赖**这两个目录
里的任何文件。

## 2. 为什么摘出来

* 它们是**站点运维**问题，不是**联机服务**问题。每个部署者的域名、备案、证书、
  静态托管方式都不一样，硬塞进交付包只会让包更大、门禁更难跑。
* 交付包的完整性由**另一套机制**保证，和这里的"下载哈希校验"不是一回事：
  `BUILD.txt` + `sha256sum -c BUILD.txt`（服务器上核对"传上去的文件是不是这一份"）
  仍然随主交付一起走，没有取消。

## 3. 未来开发者怎么用

1. 想搭官网：抄 `site/` 里的页面（HTML/CSS/JS 都是自包含、无外链、无框架），
   用宝塔 / 1Panel 建一个静态站点，把文件放上去即可；
2. 想要"下载完能核对哈希"：抄 `checksum/check-download.py` 的思路 —— 发布前
   让脚本比对「页面里写的 SHA-256 / 字节数」和「真实文件」，不一致就报错；
3. 两个目录都有自己的 `README.md`，写清了原来的部署方式、占位符清单和注意
   事项（**里面的域名、备案号、版本号、哈希都是占位/过时内容，必须换成你自己
   的**）。

## 4. 纪律

* 不要把真实凭据、真实备案号、真实域名、私钥提交进 `optional/`；
* 不要在主交付的脚本 / 文档里引用 `optional/` 下的文件路径 —— 包里没有它，
  引用就是死链；
* `optional/site/download/*.exe` 之类的二进制不进版本库（见 `.gitignore`）。
