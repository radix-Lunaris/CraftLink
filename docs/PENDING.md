一、**两个概念，别再搞混**（这一轮把它们彻底分开了）
------------------------------------------------------------

    房主（owner）   = 建房的那个人。房间的寿命绑在他身上：他离开房间，
                      房间就销毁。房间列表里「房主（建房的人）」这一列。
    当前主机（host）= 房间里的一个【位置】，Minecraft 的连接绑在它上面。
                      谁先认领谁持有；只有「释放主机身份」/离开房间/被踢
                      才会空出来。列表里「当前主机」这一列。

用户的原话：「不是说这里一定得显示房主，房主不一定就是host」——对，两列分开，
列表同时显示两个名字，谁也不冒充谁。

    房间名（玩家看的）  我的世界 一号
    房间 ID（程序用的） %E6%88%91%E7%9A%84%E4%B8%96%E7%95%8C%20%E4%B8%80%E5%8F%B7

房间名 → 房间 ID 由客户端自动做（`protocol.room_token`），中继侧同规则
（`server/room_names.py`）。老客户端发裸名字也能用：中继把两种写法归一化成
同一个房间 ID（幂等），所以**旧客户端连新中继、新客户端连旧中继都还能用**。

五、**反代隐藏面板：已完成的结论**（用户原话「太棒了，成功隐藏面板」）
------------------------------------------------------------

1Panel「反向代理」两个字段都要**带结尾斜杠**：

    代理路径   /wzshapRvDhjmfdtm/
    上游地址   http://127.0.0.1:19102/     ← 少了这个斜杠就 404

少了上游那个斜杠时，前缀不会被剥掉，面板收到 `/wzshapRvDhjmfdtm/index.php`，
容器里的 `location ~ \.php$ { try_files $uri =404; }` 直接 404；
而不带文件名的同前缀请求会被 `location /` 兜底成首页 ——
现象就是"页面能开、样式和按钮全 404"。

用户以后可能换端口（原话「以后再换个端口」）：换端口 = 改上游地址那一行，
面板侧不需要任何改动。

面板侧另外加了三处"防手滑"（已在 deploy 包里，随上传生效）：
* 不带结尾斜杠自动 301 到带斜杠
* `<head>` 里 `<base href>`（基址按 `REQUEST_URI` 算，反代前缀下才算得对）
* `redirect()` 自动补面板基址，不再跳出反代前缀

排查手册写在 `docs/HIDE_PANEL_ENTRY.md`（含从公网实测的四个地址与状态码）。
