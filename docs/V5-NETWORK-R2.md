# v5.0.0 network-r2：刷新／取消短连接修复

## 已复现的问题

Minecraft 服务器列表刷新会创建、结束或取消短 TCP 连接；本工具不解析游戏协议，任何 TCP 应用都可能出现同样的行为。本地使用真实 HostCore/PlayerCore、中继与 AutoPeer UDP 承载复现：12 次正常短连接结束不拆 P2P，混入提前取消的连接后，第 4 次探测使共享承载关闭。最先关闭时，UDP 最近收包与正常长流 PONG 均仅过去 0.406 秒；触发关闭的是一个对端已不存在的短流，其 PONG 等待超过约 2 秒。

原因是 DirectPath.close() 关闭了多个逻辑流共用的 AutoPeer。短流错误被升级成整个共享承载故障，其他正常流随之回落；打洞看门狗又会清理已关闭承载对应的旧洞。

## 修复边界

- DirectPath 仅拥有该逻辑流的直连订阅；移除订阅不关闭共享 UDP。
- 新流收到中继上的有效端到端 ACK 后，才准许接入共享直连承载。两端尚未配对的探测流不能借用健康 P2P 后再用其缺失的应答判死共享隧道。
- 未确认配对的应用流中继关闭时直接结束该流，不留作恢复任务。AutoStream 尚未从本地应用读出数据，发送窗口仍为零；已配对应用流与独立网络隧道继续保留原恢复流程。
- 已验证的独立网络会话探测超时可以关闭共享承载；实际 UDP 写失败、部分帧失败、外层帧损坏仍由 AutoPeer 废弃物理承载。
- 已通过外层帧解析的单流偏移／窗口错误，只 RESET 对应逻辑流，不关闭其他流共用的承载。
- 界面仍显示应用实际使用的路径。新应用流先走中继时，另行注明“P2P 网络隧道仍就绪”，避免把正常的中继优先准入误读成打洞断开。
- 10 个手动网络核心与 3.9.20Full 固定指纹一致。服务端协议、手动中继／直连核心没有改动。

## 本地验证

- 44 项统一回归通过，91.189 秒，见 logs/r2-regression.log。包含新增短流超时隔离、单流协议错误隔离、已验证网络会话物理故障处理，以及真实 TCP/UDP 的 12 次刷新／取消测试。
- 刷新回归检查两端原应用 writer、UDP socket 和 AutoPeer 均保持；等待超过旧故障阈值后仍为 direct，取消的临时流全部清理，原连接继续传输。
- 面板兼容入口进一步统一到 rebuild.sh panel；最终 9 项脚本行为测试通过，见 logs/r2-panel-script-tests.log。包含构建／启动／就绪失败、旧入口约束、离线镜像验证／载入与免编译启动。
- 两份 Windows EXE 从本目录重新构建并自检，修订号 network-r2；具体 SHA256 和自检结果见 docs/client-artifacts.json。

面板真实镜像构建／运行结果见 docs/V5-PANEL-BUILD.md。公网真实 NAT、Minecraft 服务器列表按钮与多人游戏仍由用户在两端实测，不能用本地回声服务代替。

## 使用与验收

两端均换用本目录的 CraftLink.exe 或 CraftLink-console.exe，窗口／日志须显示 network-r2。服务端网络代码沿用当前已更新的 v5。Linux amd64 VPS 上传完整配套包后可运行 `bash /opt/mc-link/rebuild.sh panel --prebuilt-panel`，直接载入已实测的随包面板镜像，不需要为了此次客户端修复重启中继。

建议保留一条已连接的应用 TCP 流，同时反复刷新服务器列表，覆盖探测正常结束和未完成时再次刷新；观察原游戏连接继续、P2P 端点不因探测而重建。随后真实阻断直连，确认仍能自动回落并恢复。
