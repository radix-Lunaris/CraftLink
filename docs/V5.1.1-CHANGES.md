## 迁移已有 VPS：先迁移，再覆盖

请先备份原部署目录及 .env、panel/config.php、panel/config.local.php。将本包的 scripts/deploy_config.py 与 scripts/migrate_config.py **单独上传到临时目录且放在一起**，不要先覆盖旧 Compose。

```bash
python3 /临时工具目录/migrate_config.py --from-dir /opt/mc-link --output /opt/mc-link/.env --check
python3 /临时工具目录/migrate_config.py --from-dir /opt/mc-link --output /opt/mc-link/.env
```

迁移读取旧 Compose 的实际渲染结果，并尽可能比对运行容器。已有 .env 或目标配置冲突则停止；不覆盖、不猜测、不改数据库。配置路径在根目录或外部私有目录，不能放进 panel/server 构建上下文。

已有目标文件需要补齐参数时，先保存 .pre-migration.bak，然后原子替换。再次运行相同迁移不写文件。Linux 配置权限为 0600。特殊字符使用迁移工具编码，部署不得 source/eval 该文件。

迁移完成后上传新版，保留三份私有配置，再执行：

```bash
python3 /opt/mc-link/scripts/deploy_config.py
bash /opt/mc-link/rebuild.sh all --prebuilt-panel
```

需要重启中继，正在玩的连接会断开。只处理面板可指定 panel。预检失败在构建、停止、替换容器之前返回。原 mcr/mcp 快捷命令继续指向原目录，本轮不改全局快捷方式。

自定义目录和配置路径：

```bash
MCLINK_HOME=/自定义部署目录 MCLINK_ENV_FILE=/私有目录/runtime.env bash /自定义部署目录/rebuild.sh all
```

服务器／客户端版本校验保持严格，需要两端客户端和中继一同更新为 5.1.1。修改宿主中继端口后须同步客户端已有 server_port，不自动覆盖用户配置。内部 TCP/STUN 协议端口和打洞算法不改。

## 配置入口

- DB：MCLINK_DB_HOST、MCLINK_DB_PORT、MCLINK_DB_NAME、MCLINK_DB_USER、MCLINK_DB_PASSWORD。
- 管理：MCLINK_ADMIN_API_TOKEN、MCLINK_ADMIN_API_PORT、MCLINK_RELAY_API_URL；改 API 端口时 URL 必须对应实际地址和端口。
- Docker：MCLINK_DOCKER_NETWORK、MCLINK_RELAY_CONTAINER、MCLINK_PANEL_CONTAINER、MCLINK_STATUS_VOLUME。
- 公共端口：MCLINK_RELAY_PUBLIC_PORT、MCLINK_PANEL_BIND、MCLINK_PANEL_PORT。
- 文案：MCLINK_PANEL_TITLE、MCLINK_PANEL_ICP、MCLINK_PANEL_COPYRIGHT。
- 客户端：现有 server_host/server_port，新增 update_url；首次／恢复默认的环境入口见 README.md。

所有原有效参数在保值导出时迁移。省略非敏感项沿用原默认，不重置数据库内保存的面板开关或容量设置。

## 验证与边界

具体结果在 docs/V5.1.1-VALIDATION.json。真实容器使用一次性 MySQL 8、随机测试凭据和独立网络，验证 FPM HTTP 查询、账号登录、管理 API 鉴权与特殊字符保值，未连接生产数据库。

本机临时 Docker 无 iptables，测试采用临时 extra_hosts 绕过 Docker 内嵌 DNS；产品 Compose 不包含该绕过。自定义网络与命名配置经过渲染和容器连接验证，不将本机映射测试冒充公网／VPS DNS 验收。

旧公开历史扫描通过不代表从未泄露；旧交付含过凭据，轮换仍是后续独立维护事项。本轮没有 API 扩展、Host 漂移、Mod 或网络算法修改。
