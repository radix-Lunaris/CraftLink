# v5.1.7 TCP/UDP 同端口转发

Player 的本机代理端口同时监听 TCP 和 UDP。Host 将 UDP 数据报转发到与 TCP 相同的后端地址和端口。UDP 保留报文边界，回复发回对应玩家的本机 UDP 源端口。

手动中继通过中继的 UDP 公网端口转发。手动直连使用已打洞的 UDP socket。AUTO 的 UDP 转发先使用中继，在每对 Host–Player 的直连 UDP 探测验证后使用直连，直连失效时回落到可用的 UDP 中继。

中继和两端客户端需同步更新。容器将中继公网端口同时发布为 TCP 和 UDP。VPS 防火墙及云安全组需放行与 TCP 相同的 UDP 端口。部署仍需保留原有 STUN 端口映射。

以 Simple Voice Chat 独立服务器为例，将模组的 UDP 监听端口配置为 Minecraft 的端口，并确认服务器查询功能没有占用同一个 UDP 端口。如果模组显式配置了客户端连接地址或端口，该值需要和 Player 的本机代理入口匹配。局域网开放世界的模组端口行为需要另外实测。[Simple Voice Chat 服务器配置](https://dev.modrepo.de/minecraft/voicechat/wiki/server_config)

多人打洞时，中继标注协调消息的实际发送者。Host 等待候选、同步起跑和清理旧轮次消息时按玩家筛选。RTT 广播按房间合并，Host 心跳超时只清理当次失败的控制连接。AUTO 回落会从中继重新通告接收窗口，TCP 后端传输关闭后及时释放会话。
