## 本地验证内容

统一入口：`python -B tests/run_all.py`。测试使用真实本地 TCP、中继服务端、RoomSession、HostCore、PlayerCore，以及真实 UDP 承载；Minecraft 后端使用校验字节的测试服务，不冒充真实 Minecraft 实测。

新增完整启动测试配置真实本地 STUN 应答器，执行原版 NAT 测量、入站探针、候选交换、实际打洞及 UDP 握手，不注入已建立的 PeerLink。Host 目标端口最初无人监听、Player 没有应用连接。覆盖 AUTO 先建中继网络隧道、升级、备用重接、回退；全部 STUN 无响应仍有可用中继；手动直连；AUTO → 手动直连 → 中继的策略切换；网络身份／方向拒绝。稍后启动任意 TCP 服务并成功传输二进制数据，不涉及特定游戏协议。

覆盖内容还包括：

- 中继先传业务；直连升级、业务黑洞而保活仍通的回退、未确认数据补传；原本地 TCP socket 保持。
- 实际 UDP 升级后切断备用中继、认证重接、再次回退，始终只连接一次游戏后端。
- 三玩家分别直连／中继／回退，互不串流；同一玩家新增 TCP 流仍先中继。
- 分片解析、重复、乱序、半关闭、RESET、慢接收端、小窗口、缓存预算、双路超时和切换退避。
- 版本旁路开启时仍拒绝无 AUTO 能力客户端；Owner 与 Host 权限；匿名凭证重用。
- 恢复端点、成员、凭证、Host 代次校验；过期或不一致上报不会冒充直连；结束的流不能复活。
- 房内由游客登录账号后更新恢复凭证，保留原游戏 socket；使用真实 MCLinkEngine 验证。
- 手动中继回归；手动 STUN 使用原承载并验证服务端不转发游戏业务。
- 严格 UDP 队列满不确认丢失数据、发送超时明确报错。
- 逐玩家 IP、IPv6 端点、真实路径汇总；打洞成功不等于业务直连。

故障恢复计时断言测量“直连业务黑洞后，经中继恢复的首个游戏字节”，目标小于 3 秒；不把整段大文件传完的时间当作故障检测延迟。
