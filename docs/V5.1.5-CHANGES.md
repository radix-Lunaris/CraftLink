# v5.1.5 连接恢复候选

本版处理 Host/Player 临时网络故障后假在线、终止连接未释放、后端卡顿后无法重新接入，以及 AUTO 恢复期间的状态误报。基线为 v5.1.4 / 9ae0b2b；本版修订号 recovery-r1。尚待用户 VPS、真实 NAT4 和 Minecraft 验收。

## 行为

- Host 控制连接每 3 秒 PING，9 秒无匹配 PONG 判失效；分片控制行先完整组装。旧代隧道失效后重建，异常退出的池任务自动补齐。
- 终止连接双端同时关闭，默认等待 2 秒，超时或取消后 abort；真实传输错误用复位结束代理链，避免错误转为正常 FIN 后被积压数据拖住。正常 EOF 和正常慢接收保持原字节转发与背压。
- 转发任务独立观察传输关闭和内核错误，不因另一方向 drain 阻塞而永久持有旧后端。
- 引擎保存用户连接意图和恢复代次。意外断线为 HOST_LEFT，主动停止才为 HOST_STOPPED。原先已开始连接的成员自动恢复工具通道；空闲成员不自动开始，游戏掉线后由玩家重进。
- 停止、退出、被踢、关房、释放 Host、恢复超时会取消恢复。迟到的重建不能重新启动，旧 teardown 不能移除新会话；Host 身份已变化时停止恢复，不自动转成 Player 或抢占。
- AUTO 保留原逻辑流、重放与去重算法；回退中继未验证就绪时显示恢复中。独立网络通道和实际应用流继续分别展示。

## 控制协议兼容补充

恢复房间成员连接的 JOIN 增加可选 `recover=1`，不进入原始应用数据。仅引擎的恢复流程使用；普通 CREATE/JOIN 不使用。

服务端要求同一 client_id、原成员凭据匹配、身份仍有效、成员未被主动移除，并在认证等待后重新核对当前成员对象。验证通过后使用既有 detached 座位交接规则，保留原 Owner/Host 身份并清理原传输会话。错误凭据和已被踢/退出/超时的恢复请求被拒绝。普通重复登录沿用原行为，不获得额外接管权限。此字段不是新的外部 HTTP API。

## 保留范围与指纹

STUN/NAT/打洞/UDP、手动直连算法、原始中继业务字节、容量与权限、房间正常寿命、手动热切换、多流、列表刷新、无游戏监听时建立通道继续使用现有实现。Panel、桌面布局和字体不变，配置与凭据不变。

原 docs/manual-core-baseline.json、network-core-baseline.json、ui-controller-baseline.json 未整体重置。docs/recovery-change-allowlist.json 逐项记录本轮获准变化的 9 个核心文件、10 个控制器方法及新指纹；其余核心保持原指纹。必须结合本版故障测试与原有全量测试验证，不能单靠新指纹声称正确。

## 平台与保证边界

TCP 保活默认空闲 9 秒、间隔 3 秒、3 次探测，系统不支持时记录回退参数；保活不等同于游戏登录成功，不按业务静默时间踢人。

Linux 故障注入验证：后端暂停读取期间收到实际 TCP RST，旧流可释放。Windows 可能将连接重置的交付延后至暂停读取结束，本版验证恢复读取后旧流及时释放、新流可用；不承诺游戏线程冻结时游戏内部立即出现退出消息。

关闭已经终止的传输允许丢弃不可再交付的缓冲；不会把底层已损坏的手动 TCP 会话伪装成可恢复字节流。AUTO 的正常路径切换继续由既有确认和重放维持连续性。

## 验收与上传

自动测试结果见 V5.1.5-VALIDATION.json。原故障测试的修复前失败记录及完整过程日志位于忽略的 logs，不随公共源码发布。

完整候选在 dist/v5.1.5Full。上传流程见 DEPLOY-UPLOAD.md。中继和两端客户端必须同步为 5.1.5；Panel 复用原 5.1.1 离线镜像，不重新标记镜像版本。本轮没有 push、VPS 部署或正式版本标签。

真实验收：两端在原 NAT4 环境分别切网、模拟后端卡顿后重进、Player 断网后重进；可建立 P2P 的环境另测 AUTO 回退。记录双端和中继日志，核对无需重新点击工具连接、无需游戏内 /kick；游戏自身或 Mod 保留身份的故障须根据日志另行区分。
