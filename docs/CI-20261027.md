# 首次自动检查失败与修正

首次 dev 推送对应运行：
https://github.com/radix-Lunaris/CraftLink/actions/runs/40377102785

Windows 上 74 项回归通过（103.102 秒），之后生成交付清单时中文输出遇到 cp1252 编码失败。工作流统一设置 PYTHONUTF8=1、PYTHONIOENCODING=utf-8，保持中文诊断文字。

Ubuntu 上旧设置优先测试只设置 APPDATA，实际 Linux 读取 XDG_CONFIG_HOME。测试现在同时指定正确的 Linux 临时配置根目录，不修改生产配置路径或身份目录。

热切换测试原来同时启动新 Host 与 Player，没有等待新的 Host 控制连接就绪，可能与旧连接的 HOST_STOPPED 清理交错。现在先启动 Host，并等待服务端观察到不同于旧连接的新 host_writer，再启动 Player，和原 start_engines 的启动顺序一致。仍验证 AUTO→手动直连→手动中继、不依赖应用监听、真实 UDP 载体就绪、AUTO 管理器退出及无应用会话泄露；未跳过测试、扩大超时或改动网络核心。

修复后本地 Windows Python 3.11 的 7 项针对性测试通过（6.481 秒）；本地 Linux Python 3.14 的同组 7 项通过（6.101 秒）。GitHub 的 Python 3.11 双平台完整检查另行核实，最终结果直接记录在该提交的 Actions 运行中，不以本地针对性测试代替远端完整检查。

此次只修 CI／测试及许可证展示，应用版本维持 5.1.3，不重编客户端或修改已交付 EXE。master 仅新增与 legacy 逐字节相同的 GPLv3 LICENSE，dev 和 legacy 原许可证不改。未部署 VPS，不改默认分支或生成正式发行标签。
