# v5.1.5 连接恢复修复执行约定

批准日期：2026-11-07。基线：dev / v5.1.4 / 9ae0b2b。

修复 Host 切网后假在线、后端卡顿后新连接不可用、Player 断线后旧连接残留、AUTO 中继回退后的失效。现场没有日志，实际游戏和公网验收必须独立记录，不能以模拟通过冒充完成。

## 用户确认的恢复行为

已点击开始连接的 Host 和 Player 在临时网络故障后自动恢复工具连接；游戏已掉线时由玩家手动进入。空闲成员保持空闲。主动停止、退出、踢出、关房、释放 Host 和身份失效终止恢复。房间过期不自动重建，不抢占其他 Host。

## 实施与默认参数

1. 清理幂等、双端先关闭后并行等待；终止连接关闭默认预算 2 秒，超时或取消时 abort。数据库和 UI 不阻塞 socket 释放。正常慢接收保留背压。
2. Host PING 每 3 秒、有效 PONG 超时 9 秒；检测不被 drain 阻塞。成员阈值保留。TCP 保活空闲 9 秒、间隔 3 秒、3 次，平台回退记录实际结果。
3. 维护连接意图与恢复代次，合并重复恢复。退避沿用 0.5/1/2/4/8/15 秒，总窗口 60 秒。HOST_STOPPED 仅表示主动停止，意外断线为 HOST_LEFT；2.5 秒通知宽限保留。
4. 控制连接恢复后清理旧代隧道并补齐池。Player 单流故障只清该流，保留监听和其他流。旧任务不能拆除新代连接。
5. AUTO 分别观察网络会话、应用流和备用连接；重附着校验身份和代次；回退保留偏移、重放和去重。失效期间现有 UI 显示恢复中。

## 冻结边界

原始中继数据格式、STUN/NAT/打洞/UDP 算法、手动直连、正常热切换、权限、容量、房间寿命、UI 布局字体、Panel、凭据与部署配置不改。网络层不依赖游戏监听、登录或业务保活。旧基线保留，只有逐项列明的生命周期方法允许变化，禁止整体刷新指纹。不得以新连接为由取消同一玩家其他合法 TCP 流。

## 验证门槛

- 先记录失败测试：无 PONG 假在线、串行清理背压、意外中断误发 HOST_STOPPED、迟到恢复越过停止。
- Windows/Linux TCP 故障注入、后端暂停 5/30/90 秒后恢复、断线重进、多人及多流、取消/停止/踢出/关房竞态。
- 原有完整回归、UI 审计与未修改核心指纹必须通过；禁止放宽旧断言或删测试。
- Host 控制失效 12 秒内退出正常在线；中继健康且 RTT ≤200 ms 时网络恢复后的接入目标 15 秒内；AUTO 黑洞回退沿用 ≤3 秒目标。
- 正常传输字节顺序与哈希一致，无长期残留任务/连接/无界缓存。
- 公网 NAT4 和真实游戏由用户验收；真实 P2P 回退另在可打通环境验收。
