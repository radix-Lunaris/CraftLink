# v5.1.6 切网后的房主身份与开服通道恢复

## 现场与定位

用户反馈切换网络后大厅的房主列变为横线，主机列仍有名字。
提供的客户端日志显示，房间成员连接在网络故障后恢复失败，达到
60 秒重试窗口后停止恢复，但独立的 Host 控制通道继续重试并重新就绪。
随后重新加入房间时，连接模式从 AUTO 变为中继。

源码存在与现场相符的通路。成员身份超时导致原房间销毁后，独立
Host 控制连接仍可进入旧式 HOST 建房入口，生成没有 Owner 的房间。
缺少现场服务端日志，无法核对每一步服务端清理的确切时刻。

## 修复

- 房间身份恢复前，先停止旧业务会话。清理失败则继续报恢复失败。
- 自动重连进入终态时，后台清理会话，并携带恢复代次，避免迟到清理影响新连接。
- 桌面 Host 握手增加 member=1。中继检查当前房间、房主、主机位、
  成员状态和身份凭据，确认后只附着原房间对象。
- 原房间在握手期间被销毁或替换时拒绝附着。
- 免登录桌面 Host 回传服务端发放的游客凭据。
- 原始独立 HostCore 接口保留旧式建房默认行为。桌面会话显式要求成员身份。

房主与主机可以是不同成员。身份等待和房间超时清退继续使用现有规则。

## 验证与验收

专项回归覆盖原房主身份恢复、错误凭据、掉线成员、旧式无房主房间、
房间销毁后的 Host 连续重试、重连终态清理与代次保护。
2026-11-14 本地 Windows 回环环境完整回归 96 项通过，耗时 127.526 秒。
NAT、打洞、UDP 承载等手动核心原始指纹检查通过。

真实切网验收需同步更新中继与两端客户端，再检查短暂断网恢复、
超过身份超时窗口后的房间销毁、Host 与 Owner 不同成员等场景。
本候选尚待 VPS 和真实网络验收。
